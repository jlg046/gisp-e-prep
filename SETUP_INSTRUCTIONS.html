Central Progress Website — Setup Guide

One-time setup

This version keeps GitHub Pages as the public website and uses Supabase as the central database. Students use a program username + PIN; no Bucknell SSO or institutional identity provider is required.

Already using the earlier 6-exam Supabase version?

Do not rerun the full database setup. Instead, open MIGRATE_TO_18_EXAMS.sql, paste it into Supabase SQL Editor, and run it once. It preserves existing students/results while adding exam-set and difficulty fields and expanding the accepted exam range from 6 to 18.

1. Create a Supabase project

  1. Create/sign in to a Supabase account and create a new project.
  2. Keep the project URL handy.

2. Create the database

  1. Open database_setup.sql from this website package in a text editor.
  2. Find CHANGE-ME-ADMIN-PIN and replace it with the administrator PIN you want to use.
  3. In the Supabase Dashboard, open SQL Editor, create a new query, paste the entire SQL file, and run it once.
The SQL creates student records, session records, exam-attempt records, and restricted database functions used by the browser application. PINs are stored as SHA-256 hashes rather than plain text.

3. Connect the website to Supabase

  1. In Supabase, locate your Project URL and the browser-safe publishable key (or legacy anon key).
  2. Open assets/config.js.
  3. Replace PASTE_YOUR_SUPABASE_PROJECT_URL_HERE with your project URL.
  4. Replace PASTE_YOUR_SUPABASE_PUBLISHABLE_OR_ANON_KEY_HERE with the publishable/anon key.
  5. Save the file.

4. Upload this revised website to GitHub

  1. Back up your current repository if desired.
  2. Upload the contents of the GISPE_Central_Progress_Website folder to the repository root, preserving the assets, student, and admin folders.
  3. Make sure index.html is at the repository root.
  4. Commit the changes. GitHub Pages will publish the revised site from the same branch/folder you already configured.

5. Create student logins

  1. Open your public website and choose Administrator login.
  2. Use the admin PIN you put into database_setup.sql.
  3. In the administrator dashboard, enter a student name, username, PIN, and optional cohort.
  4. Give that username and PIN to the student.

6. Student workflow

  1. The student opens the Student Portal and signs in with the username/PIN you created.
  2. They take Exam 1 as the baseline and submit it.
  3. The result, domain scores, and missed-item remediation are written automatically to Supabase.
  4. The student can later sign in from another browser/device and retrieve the same history and remediation.

7. Administrator workflow

The administrator dashboard loads all student records and exam attempts directly from the database and refreshes automatically every 20 seconds. It shows baseline score, latest score, change from baseline, weighted mastery, weakest domain, cohort priorities, the domain mastery matrix, and recent submissions.

Important limitation of this simple-login version

This is deliberately not institutional authentication. It is appropriate only while you are comfortable treating the program data as non-sensitive. For FERPA-protected or otherwise sensitive student records, the next step should be Bucknell SSO plus stronger row-level authorization and an institutionally approved hosting/data architecture.
